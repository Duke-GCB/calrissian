# CWL v1.1 test 199: stdin shortcut output formatting

The full CWL v1.1.0 run on October 27, 2026 found an additional failure in
`stdin_shorcut` (the upstream test label). It runs `tests/wc-tool-shortcut.cwl`
with `tests/wc-job.json` in `debian:stretch-slim`.

The tool binds its File input using the CWL `stdin` shortcut, runs `wc`, and
captures stdout in `output`. Both expected and actual output contain the same
counts: **16 lines, 198 words, and 1111 bytes**. Their padding differs:

| Result | Content, using a string representation | Bytes | SHA-1 |
|---|---|---|---|
| Expected | `'     16     198    1111\n'` | 24 | `2936abd60952276ffbf91d709b19c6c48c263947` |
| Actual | `'  16  198 1111\n'` | 15 | `631bfbac524e2d04cdcc5ec33ade827fc10b06ae` |

The expected padded string was checked against the upstream expected checksum;
the actual content was read from the output PVC. This is a byte-level
conformance failure despite matching numeric results.

Calrissian implements stdin through shell file redirection. A possible reason
for the padding difference is `wc` seeing a regular file descriptor instead of
a pipe, which can change its output field widths. That explanation has not yet
been verified with a controlled comparison in the same image. The run does not
show missing input data or incorrect numeric counts.

No implementation change or test-expectation override was made for this case.
See the [full run log](../../conformance/results-v1.1.txt) for the reported
comparison failure.
