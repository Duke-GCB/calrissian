# CWL v1.0 test 173: Docker ENTRYPOINT usage

## Test specification

Test `173` (`docker_entrypoint`) in the CWL v1.0.2 conformance suite runs
`v1.0/docker-run-cmd.cwl` with `v1.0/empty.json`. It belongs to the
`command_line_tool` and `docker` categories.

The tool declares `DockerRequirement.dockerPull: bash:4.4.12`, no inputs,
and this command:

```yaml
baseCommand: ["-c", "echo 'moo' > cow"]
```

The test relies on the image's Bash entrypoint to execute the arguments,
effectively running `bash -c "echo 'moo' > cow"`. Its required output is a
File named `cow`, containing `moo` followed by a newline. The expected size
is 4 bytes and its checksum is
`sha1$7a788f56fa49ae0ba5ebde780efe4d6a89b5db47`.

## Observed result

The local CWL v1.0 run reported:

```text
Error collecting output for parameter 'cow':
Did not find output file with glob pattern: ['cow'].
Test 173 failed
Returned non-zero
```

The full suite reported **195 passed, 1 failure, and 1 unsupported feature**.
Test 173 was the failure. See the [run log](../../conformance/results-v1.0.txt).
These results describe that run; they are not a claim about all Calrissian versions.

## Implementation and likely cause

In [calrissian/job.py](../../calrissian/job.py), `container_command()` always
returns `['/bin/sh', '-c']`. `container_args()` joins the quoted CWL arguments
into one shell string and appends any stream redirections.

Setting the Kubernetes container `command` overrides the image's entrypoint.
Consequently, the tool's `-c` argument is interpreted through Calrissian's shell
wrapper rather than being passed to the image's Bash entrypoint. This command
construction strongly indicates why the expected `cow` file is missing. The
saved run log reports output collection failure but does not retain the task
container's stderr, so the exact shell-level error has not been confirmed.

The wrapper was introduced in commit `09261991` (December 19, 2018),
“Rework command/args to run as sh -c”. Its documented purpose is implementing
CWL stdin/stdout/stderr redirection inside containers: a shell interprets
`<`, `>`, and `2>` instead of passing them as ordinary program arguments.
Applying that wrapper universally also bypasses entrypoints for tools that
do not need stream redirection, as in this test.

## Reproduction

After preparing the conformance environment and staging its test data, run
from the repository root:

```sh
task conformance:test VERSION=1.0 ID=173
```

The task creates a separate Job, saves logs, and collects single-test badges.
This document records the diagnosis; it does not implement an entrypoint fix.
